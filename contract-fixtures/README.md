# Contract fixtures

Golden JSON consumed by both the PHP (Pest) and Dart test suites. A fixture is the
acceptance truth: add or change the fixture first, then the code on both sides.

## Placeholders

Values that differ per request are written as placeholders. Test harnesses must check
the format and then treat them as equal.

| Placeholder     | Matches                                                     |
|-----------------|-------------------------------------------------------------|
| `{{uuid}}`      | a lowercase RFC 9562 UUID (request ids are version 7)       |
| `{{timestamp}}` | an ISO-8601 UTC timestamp with seconds and `Z`, e.g. `2026-05-28T17:22:00Z` |
| `{{int}}`       | a positive integer written as a string (HTTP header values) |
| `{{cursor}}`    | an opaque signed sync cursor: base64url payload `.` base64url signature |
| `{{seq}}`       | a journal position: a non-negative JSON integer (not a string)         |
| `{{secret}}`    | a secret returned once: 48 ASCII letters and digits (A49's receipt)    |

## Layout

- `envelope/` — response envelope and error shapes (Phase 0). Each file has
  `description`, `status`, optional `headers`, and `body`. One file per error code
  (`docs/api-error-codes.md`).
- `sync/` — `/sync` ack shapes for the A29 contract (Phase 2a.1), and bootstrap page shapes
  (`bootstrap_entities.json`, A31/A32). Each has the shape with placeholders and `rules` the test
  checks in code.
  Phase 3b: `profile_update_mutations.json` and `user_entity.json` (`{{user_id}}` is the caller's
  id, substituted by the test).
- `auth/` — request bodies for the auth endpoints (A33: `register_request.json`), with `suites`
  and `rules` like the sync files. A49: `delete_me.json` (both suites: the request, the 202 with
  the once-returned receipt, the wrong-password error) and `account_deletion_status.json` (both
  suites: the status in each state). A50: `forgot_password.json` (both suites: the request and the
  uniform 202) and `reset_password.json` (both suites: the request, the 204, the invalid-code and
  weak-password errors).
- `profile/` — `countries.json`: the ISO 3166-1 alpha-2 list (generated by
  `scripts/gen-countries.php`, which also writes the byte-identical copies `api/resources/` and
  `app/assets/` ship) that the server validator and the app's picker share.
- `habit/` — Phase 4.1 (A34, A35): `habit_mutations.json` (update, archive, restore),
  `log_increment.json` and `next_effective_date.json`, as step-by-step cases the PHP suite replays.
  Phase 6.6 (A51): `habit_delete.json` (both suites: the mutation and ack, the stale conflict, a
  log write to a deleted habit, the journal a delete produces, the habit tombstone in a pull).
- `rewards/` — Phase 5.1 (A39 to A42): `rewards_response.json` (GET /rewards) and `freezes_response.json` (GET /freezes). `sync/reward_state_entity.json` is the read-only reward entity. Phase 5.2a (A43): `sync/ack_xp_delta.json` (xp_delta on log acks) and `next_refill_on` in `freezes_response.json`. Phase 5.2b: both rewards responses also feed the Dart `RewardsService` tests. Phase 5.2c (A46): `sync/ack_xp_delta_wire.json` (Dart only) pins how the engine's AckWatch reads xp_delta from an ack.
- `exports/` — Phase 6.1 (A48): `export_job.json` (both suites: a job in each status and the list), `export_manifest.json` (php: canonical JSON and the HMAC under a test key, tampered cases), `export_csv.json` (php: A16 neutralisation and quoting). `envelope/error_410_export_expired.json` is the new error code.
- `insights/` — Phase 5.3a (A47): `insights_responses.json`, GET /insights for a week, a month, a category filter, an empty window, a protected period, an archived habit and two timezones. PHP replays each case through HTTP; Dart decodes each expected body.
- `domain/` — business rules (Phase 1). Each file has `kind`, `suites` (which test suites must
  consume it: `php`, `dart`) and `description`. Cases inside may narrow `suites` further.

## Domain seeds (A12)

Every domain case declares its whole world. Nothing is implied.

| Field | Meaning |
|---|---|
| `calendar` | Ordered calendar history: `effective_at` (UTC), `timezone` (IANA), `day_start_offset_minutes` (A22). |
| `habit.definitions[]` | `version`, `effective_date`, `type`, `target`, `unit`, `frequency_type`, `frequency_config`. |
| `habit.active_ranges[]` | Half-open local-date ranges `[starts_on, ends_before)`; `ends_before: null` is open. |
| `habit.logs` | `{ "YYYY-MM-DD": value }`, one row per habit and local date. |
| `protected` | Period keys with an active freeze usage. |
| `now` / `today` | The injected clock instant, or the user's local date when only dates matter. |

Values travel in wire form: binary `0`/`1` (integer), quantity a decimal string with up to three
decimals (`"2000.000"`), duration whole seconds (integer). Period keys follow A3:
`d:YYYY-MM-DD`, `w:<Monday>`.

The spec example account (May 2026, America/Los_Angeles) is in `insights.json`; its numbers
reconcile with the spec: 95/125 for May, 9/15 for the week of 25 May.
